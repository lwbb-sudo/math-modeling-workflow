# math-modeling-workflow

**交互式数学建模全流程工作流 Skill** —— 从题目 PDF 和附件出发，经过题意拆解、问题分析、建模路线比较、模型与算法选择、计算求解、图表制作，直到完整论文初稿与系统审查。每个小阶段暂停等你确认，所有关键研究决策由你来做。

> 设计原则：**AI 负责读题、整理信息、提出选项、解释差异和执行已确认的方案；你负责在每个关键决策点选择方向。**
> 它不是一键全自动论文生成器，而是一个"逐阶段讲解 + 逐项确认 + 差异化设计"的研究协调层。

---

## ✨ 特性

- **全程参与**：14 个小阶段，每个阶段自动完成一个完整任务后暂停，展示结果、理解和风险，等你确认再继续；
- **对话内呈现**：所有候选方案、对比表格与逐项讲解直接在对话中给出，运行期间不生成报告类文档，仅在你明确要求时导出；
- **候选方案对比**：建模路线、模型、算法、数据处理、图表类型均以中文表格形式给出多个候选（含适用条件、优点、局限/风险、解释性、创新空间、实现成本、验证难度），并标明推荐及理由；
- **差异化设计**：至少构建"稳健基线 / 机理+数据融合 / 差异化路线"三条路线供比较，创新性被当作受控的设计维度，而不是强行堆砌时髦模型；
- **可视化伴侣**：在图表与技术路线图等真正受益于视觉对比的节点，用浏览器展示候选样式，而不是只报图表名称；
- **状态与回滚**：每个阶段保存状态（当前阶段、已确认决策、被放弃方案、生成文件、未解决问题），支持"返回上一阶段 / 重做第 X 阶段 / 比较另一条路线 / 暂停项目"；
- **安全边界**：永不覆盖原始输入；外部数据检索、依赖安装、发布上传等高风险操作必须单独确认；不虚构文献、结果、代码或 AI 使用记录。

## 🔄 工作流总览

| 阶段 | 内容 | 暂停时你会看到 |
|---|---|---|
| 0 | 文件接收与完整性检查 | 文件清单、缺失/OCR 风险、能否开始分析 |
| 1 | 题目初读与结构识别 | 整题概览、研究对象、全部编号任务、歧义点 |
| 2 | 逐句拆题与完整性核验 | 逐句翻译表、术语口径表、各问输入—任务—输出、漏读审计 |
| 3 | 问题重述与问题分析 | 重述草稿、每问任务分类（预测/评价/优化/拟合等） |
| 4 | 总体路线与差异化比较 | ≥3 条候选路线对比表 + 推荐 |
| 5 | 逐问模型选择 | 每问多候选模型对比表 |
| 6 | 数据方案与外部数据决策 | 附件数据结构、缺失/异常/口径问题、外部数据候选源 |
| 7 | 算法选择 | 精确算法/数值方法/启发式/智能优化对比 |
| 8 | 实验与验证设计 | 训练/验证方案、基线、指标、消融、敏感性、验收标准 |
| 9 | 逐问建模与计算 | 每问结果、诊断、不确定性、验证结论 |
| 10 | 图表与可视化伴侣 | 每个结论对应的候选图表类型、配色、布局 |
| 11 | 论文结构与逐章撰写 | 目录框架、逐章草稿（不一次性生成全文） |
| 12 | 分项审查与修复 | 假设/求解/摘要/符号/参考文献/AI 声明分级问题清单 |
| 13 | 整篇评审与提交就绪 | 评分、风险、修改建议、最终文件清单 |

每个暂停节点的固定展示格式：`已完成` → `当前理解` → `证据/数据/约束` → `候选方案` → `推荐及理由` → `创新空间与风险` → `下一阶段` → `请你选择`。

## 📦 安装

### 方式一：Claude Code

```bash
# 用户级（所有项目可用）
git clone https://github.com/lwbb-sudo/math-modeling-workflow.git ~/.claude/skills/math-modeling-workflow

# 或项目级（仅当前项目可用）
git clone https://github.com/lwbb-sudo/math-modeling-workflow.git <你的项目>/.claude/skills/math-modeling-workflow
```

### 方式二：mathmodel 桌面端

在 MathModel 的技能管理中导入本目录（或使用其技能安装入口选择该文件夹）。

安装后在对话中输入：

```text
/math-modeling-workflow
```

并附上题目 PDF 和全部附件即可启动。

## 🧩 配套技能依赖

本 Skill 是一个**总控流程层**，在对应阶段调用以下配套技能（缺失时工作流仍可运行，由主智能体自行完成等价分析，但强烈建议配套安装以获得最佳效果）：

| 阶段 | 配套技能 | 作用 |
|---|---|---|
| 1–2 | `bzd-problem-translator` | 逐句拆题、条件提取、跨问依赖 |
| 3 | `bzd-problem-restatement` | 问题重述章节 |
| 3 | `bzd-problem-analysis-checker` | 问题分类与分析框架诊断 |
| 4 | `bzd-modeling-ideas` | 多条建模路线设计与比较 |
| 5 | `bzd-model-dictionary` | 模型适配性核验 |
| 6 | `data-search` | 外部数据查找与核验（需先经你批准） |
| 7 | `metaheuristic-optimization` | GA/PSO/DE 等智能优化（确有必要时） |
| 10 | `mma-figure` → `nature-figure` / `mathmodel-figure-templates` / `paper-diagram` | 数据图表、科研模板图、技术路线图 |
| 11 | `mma-paper` | 建模、求解与论文整合 |
| 12 | `bzd-model-assumption-checker` / `bzd-model-solution-checker` / `bzd-abstract-checker` / `bzd-symbol-notation-checker` / `bzd-reference-appendix-checker` / `bzd-ai-usage-disclosure` | 分项审查 |
| 13 | `bzd-review-paper` / `mma-review` | 整篇评审与评分 |
| 按需 | `doctor` | 环境/编译诊断 |

## 📁 使用时的项目结构

启动后会在工作区自动创建独立项目目录（不修改原始文件）：

```text
数学建模项目/
├── input/            # 原始题目与附件副本
├── extracted/        # 提取的文字、表格、图片
├── analysis/         # 拆题、分析、路线比较报告
├── data/             # 处理后的数据
├── code/             # 求解代码（确定性种子）
├── figures/          # 图表
├── paper/            # 论文稿
├── reviews/          # 审查报告
└── workflow-state/   # 工作流状态（决策记录、回滚点）
```
